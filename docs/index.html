Why altergo

Multi-account, single brain.

Claude Code keeps session history locked to one account. altergo breaks that constraint — without compromising your credentials.

Two accounts, one brain

Share session history seamlessly across personal and work Claude Code subscriptions. All your context, visible from either account, always.

Zero config drama

Symlinks handle everything. No syncing, no copying, no config files to wrangle. A single setup command and you are done — undo it just as easily.

Pick up where you left off

The interactive TUI picker shows each session's project name, last modified time, size, and a preview of the final message so you always resume with full context.

How it works

Three commands to freedom.

From install to switching accounts in under a minute. No daemon, no background process, no cloud sync.

1

Install

One pip command and you are ready. No dependencies, no compilation, pure Python standard library.

pip install altergo
2

Setup

One-time configuration creates your alt account directory and wires up the symlinks automatically.

altergo --setup
3

Switch

Run altergo any time to open the interactive session picker. Arrow keys or j/k to navigate, Enter to resume.

Commands

altergoStart a new Claude session with alt credentials
altergo --resumeOpen the interactive TUI session picker
altergo --resume <id>Resume a specific session by ID directly
altergo --listPrint recent sessions as a plain table
altergo --setupFirst-time setup: create alt home, wire symlinks
altergo --teardownRemove symlinks (alt home + credentials untouched)
altergo shellOpen an interactive shell running inside alt HOME
altergo -- <cmd>Run any command with HOME set to alt directory
altergo --versionShow version number
altergo --helpShow help text

Credentials & Auth

altergo isolates credentials by setting HOME=~/.altergo for the Claude process. Your alt account's .credentials.json lives at ~/.altergo/.claude/.credentials.json.

macOS users: Claude Code may store tokens in the system Keychain rather than a flat file. This is expected — when you authenticate inside altergo, the token is stored under a separate Keychain entry keyed to your alt account email. The ~/.altergo/.claude/ directory may appear empty even though auth works correctly.

Other tools (gh, git, etc.): Use altergo shell to open a shell inside the alt HOME, then run gh auth login or configure git. Those credentials will persist in the alt HOME and be available every time you run altergo.

What gets symlinked

These paths inside ~/.altergo/.claude/ are symlinked to your primary ~/.claude/ — both accounts share them:

projects/ tasks/ session-env/ file-history/ shell-snapshots/ agents/ plans/ cache/ settings.json CLAUDE.md keybindings.json

These stay separate per account:

.credentials.json
